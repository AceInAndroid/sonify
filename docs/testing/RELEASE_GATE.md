# Sonify 真机测试上线门禁规范（Release Gate SOP）

> **核心原则**：以后所有新增功能、UI 调整、底层音频或数据层改动，**必须先在真机上实测通过，方可 `git commit` 与 `git push` 上线**。

---

## 1. 强制门禁检查表（提交前逐项打勾）

| 步骤 | 检查项 | 执行命令 / 验证动作 | 准出标准 |
| :---: | :--- | :--- | :--- |
| **1** | **测试用例同步** | 在 `docs/testing/TEST_CASES.md` 中新增或更新对应模块的测试用例 | 覆盖正向流程 + 边界/异常场景 |
| **2** | **JVM 单元测试** | `./gradlew :app:testDebugUnitTest` | **100% 通过**（0 failures, 0 errors），核心纯逻辑需配新增单测 |
| **3** | **Debug 包构建** | `./gradlew :app:assembleDebug` | 编译通过，修改文件零新增 Kotlin 警告 |
| **4** | **真机安装与启动** | `adb install -r app/build/outputs/apk/debug/app-debug.apk` 并启动 `MainActivity` | 安装成功，进程存活，冷启无崩溃 |
| **5** | **真机功能实测** | 在真机上完整走通本次改动涉及的全部 `TC-*` 用例及最小回归集 | P0/P1 缺陷数 = 0 |
| **6** | **真机视觉核验** | 对改动涉及的关键页面抓取 `screencap` 到临时目录并逐张目视审查 | 无遮挡、无裁切、对比度正常、Android 10 兼容良好 |
| **7** | **Logcat 零异常** | `adb logcat -d -s 'AndroidRuntime:E' 'FATAL:E'` | 零 Crash、零 ANR、零 OOM |
| **8** | **测试数据清理** | 清理真机上临时建的测试歌单/账号/上传文件 | 不污染用户真实曲库与配置 |
| **9** | **测试报告归档** | 新增或更新 `docs/testing/reports/` 对应验收报告 | 记录实测时间、机型、通过数、修复缺陷清单 |

---

## 2. 按改动类型选择真机回归范围

| 改动类型 | 必测用例范围 |
| :--- | :--- |
| **UI / 主题 / 歌词样式改动** | 本模块全部新增用例 + `TC-IMM-01/05` + `TC-IML-01~09` + `TC-REG-02/03` |
| **音乐库 / 歌单 / 排序 / Room 迁移** | `TC-LIB-01~10` + 覆盖安装升级冷启 `TC-REG-02/03` |
| **Subsonic / 网络流媒体 / 下载** | `TC-SUB-01~08` + `TC-LIB-09/10` + `TC-REG-03` |
| **WiFi 局域网传歌** | `TC-WIFI-01~08` + `TC-REG-03` |
| **USB 独占 / 音量护耳 / 后台播放** | 插拔 DAC 实测 + 音量保护上限与物理按键验证 + 息屏连续播放 + `TC-REG-03` |
| **版本发布前（Release）** | `docs/testing/TEST_CASES.md` **全量模块 A–G 回归** |

---

## 3. 真机不可用时的阻断策略

- **真机未连接 / ADB 离线 / 手机处于锁屏 PIN 保护状态**：
  - 严禁尝试绕过锁屏，严禁跳过真机测试直接 `git push`；
  - 必须暂停提交并在对话中明确告知用户：「代码与单元测试已就绪，请连接/解锁测试机以便完成真机测试门禁后上线」。
  - 仅在用户明确回复豁免本次真机测试时，才允许在 commit message 中注明原因并推送。
